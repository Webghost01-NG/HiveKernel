## 📌 The Core Problem: The Autonomous Agent Collaboration Crisis

In modern decentralized multi-agent systems, monolithic AI agents fail on complex multi-stage tasks. True swarm intelligence requires **subcontracting**—specialized agents outsourcing subtasks (e.g. smart contract vulnerability auditing, oracle verification, on-chain arbitrage modeling, data scraping) to peer agents in the network.

However, existing frameworks suffer from critical flaws:
1. **The Machine-to-Machine Trust Deficit**: If Agent $A$ hires Agent $B$, how does Agent $A$ know Agent $B$ did not hallucinate, fake the computation, or execute a malicious exploit?
2. **Subjective Output Incompatibility**: Smart contracts cannot natively parse or verify complex natural language or analytical outputs generated by LLMs.
3. **Absence of Autonomous Escrow**: Agents lack non-custodial, peer-to-peer escrow rails that allow instant micro-settlement without human intervention.

## 💡 The Solution: `HiveKernel`

`HiveKernel` introduces an **Optimistic Challenge & Settlement Protocol** built from the ground up in **Rust**. It brings the game-theoretic safety of Optimistic Rollups to multi-agent task execution:

```

                  └────────────────────────────────────────────────────────┘

               ▼                                                             ▼

               │                                                             │
```

## 🏛️ System Architecture

HiveKernel is organized as a high-performance modular Rust workspace:

```text
HiveKernel/
├── crates/
│   ├── hive-core/       # Core actor primitives, cryptographic receipts, state machine
│   ├── hive-p2p/        # Peer discovery, gossip transport, RFQ auction & bid matcher
│   ├── hive-escrow/     # Optimistic challenge window, verification consensus, ledger
│   └── hive-cli/        # High-definition terminal simulator & multi-agent runner
├── contracts/           # EVM Solidity smart contracts for on-chain non-custodial escrow
└── tests/               # End-to-end integration and adversarial dispute test suites
```

### 1. Cryptographic Task Receipt (`TaskReceipt`)
Every task completed by a Worker node is sealed with an Ed25519 signature over a deterministic execution digest:
$$\text{Digest} = \text{SHA256}(\text{TaskID} \parallel \text{DelegatorPubKey} \parallel \text{PromptHash} \parallel \text{OutputHash} \parallel \text{Timestamp})$$

### 2. Optimistic Verification & Slashing Game
- **Step 1 (RFQ Broadcast)**: Delegator specifies task requirements, deadline, and bounty escrow.
- **Step 2 (Auction & Assignment)**: Candidates submit bids with their reputation score and fee.
- **Step 3 (Execution & Sealed Output)**: Assigned Worker executes workload and submits signed `TaskReceipt`.
- **Step 4 (Challenge Window)**: Swarm Validators verify output integrity. If fraud is proven, the Worker is penalized.
- **Step 5 (Finality & Settlement)**: Zero-friction token release directly into Worker's crypto wallet.

## 🚀 Getting Started

### Prerequisites
- [Rust](https://www.rust-lang.org/) (version 1.80+)
- `cargo` and `git`

### Installation & Build

```bash
# Clone the repository
git clone https://github.com/Webghost01-NG/HiveKernel.git
cd HiveKernel

# Build the entire workspace
cargo build --release
```

### Running the Live Multi-Agent Swarm Simulation

Run the built-in multi-agent simulation where a **Delegator Agent**, a **Specialist Worker Agent**, and a **Validator Node** coordinate in real time:

```bash
cargo run -p hive-cli -- run-swarm --task "Security Audit of ERC-20 Staking Protocol" --bounty 250
```
